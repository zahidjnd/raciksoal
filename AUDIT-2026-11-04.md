## C. Catatan KODE (belum dikerjakan; bahan perombakan nanti)

Urut dari yang paling berisiko ke pengguna.

1. [SELESAI: denganSetTerkunci] **Editan guru bisa hilang (lost update)** `actions.ts`: `gantiSatuSoal` membaca seluruh array `soal`, menunggu AI 20–60 detik, lalu menulis ulang seluruh array. Kalau guru mengedit soal lain (`simpanSoal`) selama menunggu, editan itu tertimpa. Sama untuk dua tab. Perbaikan: perbarui per butir di SQL (`jsonb_set`) atau kolom versi (`UPDATE ... WHERE versi = ?`).
2. [SELESAI: kunci advisory + batas proses serentak; batas harian Ganti/Ubah/Tambah 60x/guru sejak 0.16.0] **Pembatas harian tidak atomik** `mulaiBuatSoal`: hitung lalu `insert` terpisah; klik ganda/dua tab melewati 10 set/hari. `Ganti/Ubah` (30x/set) tidak punya batas harian per guru, jadi biaya AI bisa menumpuk. Selain itu tidak ada batas **set "proses" serentak** per guru/seluruh web; 15–20 guru menekan Buat sekaligus di RAM 1 GB.
3. [SELESAI: TENGGAT_SET 10 menit] **Tidak ada batas waktu total pada satu set.** `tanyaAI`: timeout 180 dtk × 3 percobaan (+10/20 dtk jeda) × sampai 9 model cadangan × beberapa tahap. Terburuk bisa puluhan menit "sedang meracik". Beri tenggat total (mis. 8 menit) lalu tandai gagal.
4. **Kunci kunci pembatas login per nama pengguna** (`masuk/actions.ts`): siapa pun yang tahu username guru bisa mengunci guru itu 15 menit dengan 5 kali salah. Pembatas juga di memori (hilang saat restart) dan Map tidak pernah dibersihkan. Cukup untuk sekarang; pertimbangkan kunci per IP+username dan tabel DB. Pembatas analisa materi (`analisaHariIni`) juga di memori.
5. **`kerjakan` berjalan di dalam proses web** (`void kerjakan(...)`). Penanganan restart sudah ada (0.8.2), tetapi pekerjaan berat dan lama berbagi RAM dengan layanan halaman. Antrean sederhana di DB (satu pekerja) lebih tahan banting kalau guru bertambah.
6. [SEBAGIAN 0.16.0: `npm run uji:pemisahan` menguji aturan 3 lewat server laptop] **Hanya fungsi murni yang punya tes** (`soal`, `skor`, `mushaf`, `akses`, `nama-file`). Tidak ada tes untuk server action (aturan 3 hanya terbukti lewat uji manual dua akun), tidak ada tes `word.ts`/prompt. Satu tes integrasi "guru B tidak bisa `cekHasil/simpanSoal/ganti/Word` set guru A" akan menjaga aturan 3 saat dirombak.
7. **`actions.ts` memuat empat urusan** (jatah, pembuatan set, edit/ganti soal, analisa materi, identitas). Pisah per urusan + satu "ambil set milik" bersama. Nama `ambilSet` dan `cekHasil` mengulang kueri + pemeriksaan pemilik yang sama.
8. **File besar:** `buat-soal.tsx` (652 baris), `soal.ts` (526), `prompt.ts` (464), `kartu-soal.tsx` (452), `word.ts` (430). Pecah per bentuk soal (tabel kode bentuk → satu objek berisi prompt, pemeriksa, tampilan web, tampilan Word) supaya bentuk baru tidak perlu menyentuh 6 file. Pelajaran 0.10.0 (bentuk baru terlewat di penjumlahan) menunjukkan risikonya.
